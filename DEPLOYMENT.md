# Lumière: Vercel + Render + Neon

## Архитектура

- Vercel собирает публичные Razor-представления в HTML. Главная, меню, контакты,
  политика, корзина и оболочки оформления/админки открываются без Render.
- Поиск и корзина работают в браузере. В localStorage остаются только ID, количество
  и способ получения, без имени, телефона и адреса.
- `/api/catalog` и `/media/...` на Vercel читают только публичное меню и JPEG из Neon,
  поэтому новые изображения не зависят от запуска Render.
- `/backend/...` — отдельный прокси серверных функций к Render. Остальной сайт
  не переписывается на Render. Прокси не передаёт заставку Render посетителю.
- До оформления интерфейс дожидается `/backend/healthz`, получает CSRF-токен,
  передаёт только ID/количество и переходит на серверную форму. Итог и наличие
  пересчитываются сервером. Повторные платежи используют ID заказа как ключ ЮKassa.
- Админка и все динамические ответы, ошибки, редиректы и CSRF: `private, no-store`
  на браузере и CDN. Cookies: HttpOnly, SameSite=Lax, Secure в production.
- Neon хранит меню и заказы в JSONB с блокировкой строки при изменении заказов;
  сессии и key ring также переживают перезапуск Render.
- Новые JPEG до 3 МБ хранятся в PostgreSQL, а не на временном диске Render.
  Имена UUID неизменяемые; кешировать разрешено только публичные фотографии.

## Отдельные ресурсы

- GitHub: `https://github.com/dima-AIi/lumiere`, ветка `main`.
- Vercel: команда `portfolio-d59d`, проект `lumiere`.
- Neon: ресурс `lumiere-db`, план `free_v3`, регион Frankfurt.
- Render: новый сервис `lumiere-api`, Docker, Frankfurt, план `free`.
- Проекты Mellow House, portfolio-platform и portfolio-backend не используются
  как цели публикации и не изменяются.

## Переменные окружения

Vercel, **только проект lumiere / Production**:

| Имя | Значение |
| --- | --- |
| `DATABASE_URL` | Добавляется отдельной интеграцией Neon |
| `RENDER_API_ORIGIN` | HTTPS origin нового Lumiere-сервиса Render, без пути |

Render, **только новый Lumiere-сервис**:

| Имя | Значение |
| --- | --- |
| `DATABASE_URL` | Pooled connection string только новой lumiere-db |
| `Admin__Password` | Новый случайный секрет; Blueprint генерирует его автоматически |
| `ASPNETCORE_ENVIRONMENT` | `Production` |
| `YooKassa__ReturnUrl` | `https://<публичный-домен-Lumiere>/Home/PaymentSuccess` |
| `YooKassa__ShopId` | Необязательно: ID собственного магазина |
| `YooKassa__SecretKey` | Необязательно: ключ собственного магазина |

Без ключей ЮKassa заказы явно демонстрационные, реальные деньги не списываются.
Не используйте известный пароль из старой истории репозитория. Он удалён из
текущей конфигурации и не должен применяться в облаке.

## Сборка

Установить Node.js 24, pnpm 11.25.0 и .NET SDK 10.0.402.

```text
pnpm install --frozen-lockfile
pnpm build
pnpm preview
```

`scripts/build-frontend.mjs` сначала компилирует приложение, затем в отдельном
режиме `StaticExport` запускает только локальный экспорт. Он не подключается
к production Neon и удаляет CSRF-токены из публичного HTML.
На Vercel официальный .NET SDK устанавливает `scripts/vercel-build.sh`.
На Render используется многостадийный Dockerfile; приложение слушает `PORT`.
Рабочий `App_Data` исключён из Git, Docker и dotnet publish.

## Миграция и перенос данных

`Lumiere/Migrations/001_durable_state.sql` добавляет таблицы без удаления записей.
Исходное меню добавляется только при отсутствии существующего меню.
Импорт объединяет заказы по ID; существующий заказ не заменяется.

Запуск с переменными нового проекта Vercel, без печати строки подключения:

```text
vercel env run -e production -- node scripts/migrate.mjs Lumiere/App_Data/orders.json
```

Если исходных заказов нет, последний аргумент опускается. Исходный файл не
удаляется и никогда не отправляется в GitHub. Миграции предпочитают direct URI,
обычные запросы — pooled URI. Npgsql проверяет TLS-сертификат.

## Проверка серверных функций

```text
dotnet publish Lumiere/Lumiere.csproj -c Release -o artifacts/qa-backend-v2
vercel env run -e production -- node scripts/smoke-backend.mjs
```

Проверка создаёт уникальную временную схему и отдельно запускает опубликованную
копию на порту 5184. Рабочие заказы и меню не изменяются. Схема удаляется после
остановки копии. Проверяются CSRF, запрет доступа в админку, серверные цены,
валидация, демонстрационный заказ, защита от повторной отправки, дробные цены,
сохранение корзины, авторизации и загруженного JPEG после перезапуска процесса.

## Автоматическое обновление

Vercel должен быть связан с репозиторием Lumiere и production-веткой `main`.
Render создаётся с `autoDeployTrigger: commit` из этого же репозитория.
Обычная отправка изменений в `main` пересобирает публичные страницы и сервер.
Изменения меню из админки сохраняются в Neon и читаются Vercel при следующем
открытии страницы; отдельная отправка Git для них не нужна.

## Ограничения бесплатных тарифов

Render засыпает после простоя. Оформление и админка могут ждать запуск минуту
или дольше, а при исчерпании квот — оставаться недоступными. Главная, меню,
контакты и локальная корзина продолжают открываться с Vercel.
Neon также может приостанавливать вычисления; до обновления публичного меню
показывается снимок, собранный из текущего исходного меню. При оформлении сервер
всегда проверяет действующее меню. Хранение JPEG расходует квоту базы Free;
для большой медиатеки понадобится отдельное объектное хранилище.
