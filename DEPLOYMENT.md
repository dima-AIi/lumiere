# Публикация Lumière: статическая демонстрация

- Публичная ссылка: https://lumiere-sigma-three.vercel.app/
- GitHub: https://github.com/dima-AIi/lumiere, ветка main.
- Vercel: существующий проект lumiere, команда portfolio-d59d.
- Render: существующий lumiere-api. Он оставлен только для совместимости старого адреса и закрывает запись; публичная витрина к нему не обращается.

## Что изменилось

Vercel публикует шесть HTML-страниц с локальными ресурсами и статическим menu.json. middleware.js пропускает только GET/HEAD, остальные методы возвращают 405 без чтения тела. Старые /Admin, /api, /backend, /register, /login и их дочерние адреса возвращают 410. Прокси к Render и запросы к Neon удалены. CSP запрещает отправку форм и подключение внешних скриптов/виджетов.

ASP.NET Core не содержит обработчиков админки, сессий, заказов и платежей. Драйвер PostgreSQL и службы работы с базой удалены. Приложение не читает старый секретный файл lumiere.json. Даже сохранившиеся переменные DATABASE_URL и Admin__Password не могут включить старые функции.

## Публикация

Перед коммитом: pnpm build, pnpm test, pnpm verify и проверка интерфейса в браузере. Push в main запускает имеющиеся публикации Vercel и Render. Проверять оба адреса: заголовок X-Lumiere-Mode: static-demo, POST /Home/Checkout -> 405, GET /Admin -> 410, Render /healthz -> mode static-demo. Пока Render не обновился, старые публичные адреса сервера ещё требуют проверки.

## Ранее сохранённые данные

Переход на демоверсию отключает использование прежней базы, но не удаляет уже существующие записи или резервные копии в Neon. Старые данные требуют отдельного рассмотрения и при необходимости удаления через владельца базы. База и другие проекты автоматически не удаляются.

## Внешние журналы

Код приложения не пишет тела запросов, посетительские данные и поисковые строки в логи. Собственные технические журналы Vercel/Render и доступность исторических публикаций управляются хостингом. Демоверсия не означает гарантированного соответствия всем требованиям закона; такой вывод требует проверки инфраструктуры и прежних данных.

## Оформление и фотографии

Верхняя полоса «Учебная витрина» убрана. Оформление имитирует оплату и показывает квитанцию с явной пометкой о демонстрации. Единственное редактируемое поле — имя без атрибута name и без формы. Значение используется через textContent только в текущем DOM; оно не добавляется в состояние корзины, localStorage, URL, логи или запросы. Адрес берётся из статического меню, доступен только для чтения и повторно формируется для квитанции из каталога. Фотографии товаров каталога загружаются eager, включая нижние категории.
